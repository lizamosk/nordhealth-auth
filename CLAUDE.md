# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Client-side only Nuxt 4 sign-up app (`ssr: false`) built on the Nord Design System web components (`<nord-*>`), vee-validate + zod, and `@nuxtjs/i18n`. `README.md` documents the design decisions and the deliberate deviations from Nord defaults; read it before changing styling or accessibility behavior. The repo root is the app; it also holds the Nord agent skill under `.agents/skills/nord-full`.

## Commands

Run from this directory. Requires Node `^22.21.0 || ^24.11.0 || >=26.0.0`.

```bash
npm run dev            # http://localhost:3000
npm run build          # production build (e2e tests run against this, not dev)
npm run lint           # ESLint (prettier runs as an ESLint rule); lint:fix to autofix
npm run format:check   # prettier --check .
npm run typecheck      # nuxt typecheck (vue-tsc)
npm test               # vitest unit tests (happy-dom)
npx vitest run tests/unit/signUpSchema.spec.ts   # single unit test file
npx vitest run -t "name"                         # single test by name
npm run test:e2e       # Playwright, desktop + mobile; builds and serves on port 3200 itself
npx playwright test tests/e2e/signup.spec.ts --project=desktop   # single e2e file/project
```

`eslint.config.mjs` imports `./.nuxt/eslint.config.mjs`, which is generated by `nuxt prepare` (runs on `npm install`); lint fails if `.nuxt/` is missing.

## Architecture

- **Routes** (`app/pages`): `/` sign-up, `/success`, plus `/sign-in` and `/dashboard` stubs (`StubPage.vue`) that exist only because the design links to them.
- **Form logic lives in `app/composables/useSignUpForm.ts`**, not the components. A single zod schema (`app/utils/signUpSchema.ts`) is the source of truth for rules and the `SignUpValues` type. Zod messages are i18n **keys** resolved at render time. Validation timing is deliberate: validate on blur first, then on every change after touch/submit. The error summary (`summary`) is only captured on a failed submit and intentionally does not update while the user edits, to avoid layout jumps.
- **Sign-up request** (`app/services/auth.ts`) is a mock (~900ms delay, no backend). `useSignUpForm` takes `signUp`/`onSuccess`/`onInvalid` options so tests and a future real API can inject behavior. The password is never stored or passed on.
- **Success page gating**: `useSignUpResult` (a `useState`) holds the result; `middleware/signup-complete.ts` redirects `/success` to `/` if there is none.
- **Theme**: `nuxt.config.ts` reads `@nordhealth/themes/lib/nord-dark.css` at build time, rescopes `:root` to `:root[data-theme="dark"]`, and inlines it in `<head>`; an inline head script sets `data-theme` from `localStorage['mode']` or the system preference before first paint. `useTheme`/`ThemeToggle` only flip the attribute.
- **Styling**: Tailwind v4 via the Vite plugin with Nord's entry (`@import '@nordhealth/css/tailwind'` in `app/assets/css/main.css`, utility prefix `n:`) plus Nord tokens/fonts.
- **i18n**: all copy is in `i18n/locales/en.json`; no hard-coded text in templates. New locales need a `nuxt.config.ts` entry and a file with identical keys.

## Nord gotchas

- `isCustomElement` matches only `tag.startsWith('nord-')`, so Nuxt components like `<NuxtLink>` still resolve. ESLint rules `vue/no-undef-components` and `vue/no-deprecated-slot-attribute` are off for this reason.
- Import components per-component (`@nordhealth/components/lib/Input`), not via the CDN script; types come from `@nordhealth/components/lib/vue.d.ts` (see `app/types/nord.d.ts`).
- `nord-icon` would fetch from nordcdn.net; every icon used must be registered locally in `app/plugins/nord-icons.client.ts`.
- Always wrap `nord-button` text in a `<span>`; a bare text child makes Lit throw "ChildPart has no parentNode" when the label changes.
- Nord forces slotted card headers to small font size with `!important`, so headings go in the card body.
- For component APIs and tokens, use the `nord-full` skill (`.agents/skills/nord-full`) instead of guessing.

## Testing notes

Unit tests (`tests/unit`) cover the schema and `useSignUpForm` only; components are covered by Playwright e2e (`tests/e2e`), including axe WCAG 2.2 AA scans of form, error, and success states in both light and dark themes. Contrast fixes in the form (`--n-input-border-color`, `--n-color-text-error`) exist because those axe scans caught them; don't remove them without rerunning e2e.
